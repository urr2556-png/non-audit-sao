# ระบบจัดทำและบริหารจัดการรายงาน Non-Audit
## สำนักตรวจเงินแผ่นดินจังหวัดสุรินทร์

> ตรวจสอบเพื่ออนาคตประเทศชาติและประชาชน

**ค่านิยม:** สัตย์ซื่อ มืออาชีพ อิสระและเป็นกลาง

โครงการพัฒนาระบบสำหรับรวบรวมข้อมูล วิเคราะห์ จัดทำรายงาน Non-Audit จัดเก็บรายงาน ติดตามข้อเสนอแนะ และเผยแพร่ผลงานที่ได้รับอนุมัติให้ประชาชนเข้าถึง

ออกแบบให้ใช้งานได้บนคอมพิวเตอร์ โทรศัพท์มือถือ และแท็บเล็ต โดยทุกระบบใช้ข้อมูลร่วมกันและมีผู้ดูแลระบบควบคุมสิทธิ์การใช้งาน

---

## 1. สถานะโครงการ

**สถานะ ณ วันที่ 12 ตุลาคม 2569**

Repository มีไฟล์ `README.md` สำหรับอธิบายโครงการ ยังไม่มีไฟล์ `index.html` และไฟล์ระบบงานอื่นในรายการไฟล์ที่ตรวจสอบ

รายละเอียดระบบและโครงสร้างไฟล์ในเอกสารนี้เป็นข้อกำหนดสำหรับการพัฒนา ไม่ใช่การรับรองว่าทุกฟังก์ชันเปิดใช้งานแล้ว

| ส่วนงาน | สถานะ |
|---|---|
| เอกสารอธิบายโครงการ | README ฉบับนี้ |
| หน้าแรกและหน้าย่อย | ต้องเพิ่มไฟล์และตรวจสอบ |
| ฐานข้อมูลกลาง | ต้องติดตั้งและเชื่อมต่อ |
| ลงทะเบียนและเข้าสู่ระบบ | ต้องพัฒนาและทดสอบ |
| สิทธิ์ผู้ใช้งานและ Admin | ต้องกำหนดและทดสอบ |
| ระบบ AI | ต้องเชื่อมต่อบริการผ่านระบบหลังบ้าน |
| การเผยแพร่เว็บไซต์ | ต้องเพิ่มหน้าเว็บและตั้งค่า GitHub Pages |

## 2. วัตถุประสงค์

1. ลดเวลาการรวบรวมข้อมูลและจัดทำร่างรายงาน Non-Audit
2. จัดเก็บข้อมูลประกอบการวิเคราะห์อย่างเป็นระบบ
3. เชื่อมโยงรายงานกับหลักฐานและแหล่งข้อมูลอ้างอิง
4. ติดตามข้อเสนอแนะ ผู้รับผิดชอบ และกำหนดเวลา
5. สนับสนุนการตรวจทานและอนุมัติโดยผู้มีสิทธิ์
6. เผยแพร่เฉพาะผลงานที่ได้รับอนุมัติให้เปิดเผย
7. ใช้ AI ช่วยสรุปและร่างข้อความ โดยเจ้าหน้าที่ตรวจสอบก่อนนำไปใช้

| 2 | ลงทะเบียน | `register.html` | สมัครและส่งคำขอใช้งาน |

| 4 | สร้างรายงาน | `create-report.html` | กรอกข้อมูลและจัดทำร่างรายงาน |
| 5 | ค้นหารายงาน | `search-reports.html` | ค้นหาตามเรื่อง หมวด ปี และสถานะ |
| 6 | จัดเก็บรายงาน | `archive-reports.html` | จัดการรายงาน เอกสาร และรุ่นของรายงาน |

**การสร้างลิงก์ระหว่างหน้าไม่เท่ากับการเชื่อมข้อมูล** การใช้ข้อมูลร่วมกันต้องมีฐานข้อมูลกลางและระบบตรวจสอบสิทธิ์ด้วย

## 4. รูปแบบหน้าแรก

หน้าแรกกำหนดให้มีองค์ประกอบดังนี้

### ส่วนหัว

- โลโก้ สตง.
- ชื่อ “สำนักตรวจเงินแผ่นดินจังหวัดสุรินทร์”
- ค่านิยม “สัตย์ซื่อ มืออาชีพ อิสระและเป็นกลาง”
- วันและเวลาปัจจุบันตามเขตเวลา `Asia/Bangkok`

### ส่วนแนะนำระบบ

ข้อความหลัก:

> ตรวจสอบเพื่ออนาคตประเทศชาติและประชาชน

ข้อความประกอบ:

> สร้างรายงาน จัดเก็บ และติดตามผลในระบบเดียว

ปุ่มหลัก:

- เริ่มสร้างรายงาน
- ติดตามผล

### เมนูและข้อมูล

- เมนูเชื่อมไปยังระบบทั้ง 12 หน้า
- จำนวนรายงานทั้งหมด
- จำนวนรายงานที่อนุมัติแล้ว
- จำนวนรายการติดตามที่เกินกำหนด
- จำนวนผลงานที่เผยแพร่แล้ว
- ฐานข้อมูลเพื่อสร้างรายงาน 18 ด้าน
- ผลงานสาธารณะ 10 หมวด

ใช้โทนกรมท่า เส้นและไอคอนหลากสี ตัวอักษรอ่านง่าย และไม่แสดงข้อความ “โหมดทดลอง”

หากโหลดข้อมูลสถิติไม่ได้ ต้องแสดงสถานะว่า “ไม่สามารถโหลดข้อมูลได้” เพื่อแยกจากกรณีที่มีจำนวนจริงเป็นศูนย์

## 5. ฐานข้อมูลเพื่อสร้างรายงาน 18 ด้าน

1. ด้านงบประมาณ
2. ด้านกำลังคน
3. ด้านเทคโนโลยี
4. ด้านกฎหมาย
5. ด้านระเบียบ
6. ด้านประกาศ
7. ด้านมติคณะรัฐมนตรี
8. ด้านคำสั่งระเบียบแบบแผนต่าง ๆ
9. ด้านหลักวิชาการ
10. ด้านคู่มือต่าง ๆ
11. ด้านแผนพัฒนาต่าง ๆ
12. ด้านมาตรฐานต่าง ๆ
13. ด้านเศรษฐกิจ
14. ด้านสังคม
15. ด้านการเมือง
16. ด้านสิ่งแวดล้อม
17. ด้านต่างประเทศ
18. ด้านระบบราชการ

ข้อมูลแต่ละรายการควรระบุชื่อเรื่อง หน่วยงานเจ้าของข้อมูล วันที่เอกสาร แหล่งอ้างอิง วันที่ปรับปรุง และสถานะการใช้งาน

เอกสารกฎหมาย ระเบียบ และมาตรฐาน ต้องตรวจสอบฉบับและช่วงเวลาที่ใช้บังคับก่อนนำไปประกอบข้อสรุป

## 6. ผลงานสาธารณะ 10 หมวด

1. ผลวิเคราะห์การจัดการน้ำ
2. ผลวิเคราะห์การแก้ปัญหาภัยแล้ง
3. ผลวิเคราะห์สิ่งก่อสร้างทิ้งร้าง
4. ผลวิเคราะห์เงินอุดหนุนเฉพาะกิจ
5. ผลวิเคราะห์การบริหารงบจังหวัด
6. ผลวิเคราะห์ปัญหาสิ่งแวดล้อม
7. ผลวิเคราะห์ปัญหาเขื่อนป้องกันตลิ่ง
8. ผลวิเคราะห์ไฟฟ้าโซล่าเชลล์
9. ผลวิเคราะห์การก่อสร้างถนน
10. ผลวิเคราะห์ระบบรายงานการเงิน อปท.

การมีหมวดผลงานไม่ได้หมายความว่ามีรายงานเผยแพร่แล้ว ระบบจะแสดงเฉพาะรายการที่ได้รับอนุมัติและกำหนดให้เปิดเผย

## 7. สถาปัตยกรรมที่เสนอ

| ชั้นระบบ | หน้าที่ | แนวทาง |
|---|---|---|
| หน้าเว็บ | แสดงผลและรับข้อมูล | HTML, CSS และ JavaScript |
| โฮสต์หน้าเว็บ | ให้บริการไฟล์เว็บไซต์ | GitHub Pages |
| ระบบยืนยันตัวตน | ลงทะเบียน เข้าสู่ระบบ และจัดการบัญชี | บริการ Auth เช่น Supabase Auth |
| ฐานข้อมูลกลาง | เก็บรายงาน ข้อเสนอแนะ และข้อมูลอ้างอิง | PostgreSQL เช่น Supabase Database |
| ที่เก็บเอกสาร | เก็บหลักฐานและไฟล์แนบ | Storage ที่ตรวจสอบสิทธิ์ |
| ระบบหลังบ้าน | ตรวจสิทธิ์ อนุมัติ เผยแพร่ และเรียก AI | API หรือ Edge Functions |
| ระบบบันทึกกิจกรรม | ตรวจสอบประวัติการเปลี่ยนแปลง | Audit Log |

### หลักการเชื่อมข้อมูล

- รายงานแต่ละฉบับมีรหัสประจำรายการ
- หลักฐานและข้อเสนอแนะอ้างอิงรหัสรายงานเดียวกัน
- การค้นหา การจัดเก็บ และการติดตามอ่านข้อมูลจากฐานข้อมูลกลาง
- หน้าเผยแพร่แสดงเฉพาะข้อมูลที่อนุญาตให้เปิดเผย
- การอนุมัติและเปลี่ยนสิทธิ์ต้องตรวจสอบจากระบบหลังบ้าน
- สถิติต้องอ้างอิงข้อมูลจริงและระบุเวลาที่ปรับปรุงล่าสุด

GitHub Pages ให้บริการหน้าเว็บแบบ Static จึงต้องใช้บริการหลังบ้านเพิ่มเติมสำหรับการยืนยันตัวตน ฐานข้อมูล และการเรียก AI ที่ใช้กุญแจลับ

## 8. สิทธิ์การใช้งานที่กำหนด

| บทบาท | สิทธิ์หลัก |
|---|---|
| ประชาชน | อ่านและค้นหาผลงานที่เปิดเผย |
| ผู้สมัคร | ส่งคำขอใช้งานและรอการอนุมัติ |
| เจ้าหน้าที่ | จัดทำรายงานและบันทึกผลตามสิทธิ์ที่ได้รับ |
| ผู้ตรวจทาน | ตรวจสอบร่างและส่งกลับแก้ไข |
| ผู้อนุมัติ | อนุมัติรายงานและการเผยแพร่ |
| Admin | จัดการผู้ใช้ สิทธิ์ หมวดข้อมูล และการตั้งค่า |

ผู้สมัครไม่สามารถกำหนดตนเองเป็น Admin ได้

การซ่อนปุ่มบนหน้าเว็บเพียงอย่างเดียวไม่ใช่การควบคุมสิทธิ์ ต้องตรวจสอบสิทธิ์ทุกครั้งที่อ่านหรือเปลี่ยนข้อมูลในระบบหลังบ้าน

## 9. ขั้นตอนการจัดทำรายงาน

1. เจ้าหน้าที่เข้าสู่ระบบ
2. เลือกหมวดและสร้างรายงานใหม่
3. กรอกข้อเท็จจริงและข้อมูลโครงการ
4. เพิ่มหลักฐานและแหล่งอ้างอิง
5. วิเคราะห์ปัญหา สาเหตุ ผลกระทบ และข้อเสนอแนะ
6. ใช้ AI ช่วยจัดทำร่างตามข้อมูลที่มี
7. เจ้าหน้าที่ตรวจสอบและแก้ไขร่าง
8. ส่งให้ผู้ตรวจทาน
9. ส่งให้ผู้อนุมัติ
10. จัดเก็บรายงานฉบับอนุมัติ
11. กำหนดผู้รับผิดชอบและระยะเวลาติดตาม
12. เผยแพร่เฉพาะฉบับที่อนุญาตให้เปิดเผย

### สถานะรายงาน

`ร่าง → รอตรวจทาน → รออนุมัติ → อนุมัติแล้ว`

หากต้องแก้ไข ให้ส่งกลับสถานะร่างพร้อมเหตุผล

การเผยแพร่เป็นสถานะแยกจากการอนุมัติ รายงานที่อนุมัติแล้วอาจยังไม่อนุญาตให้เปิดเผย

## 11. ระบบติดตามผล

ข้อเสนอแนะแต่ละรายการควรมี:

- รหัสรายงานที่เกี่ยวข้อง
- รายละเอียดข้อเสนอแนะ
- หน่วยงานหรือผู้รับผิดชอบ
- วันที่แจ้งและกำหนดแล้วเสร็จ
- สถานะการดำเนินงาน
- ผลการดำเนินงานและหลักฐาน
- ผู้ตรวจสอบผลและวันที่ตรวจสอบ

สถานะติดตาม:

`ยังไม่เริ่ม / อยู่ระหว่างดำเนินการ / รอตรวจสอบผล / เสร็จสิ้น`

รายการเกินกำหนดต้องคำนวณจากวันครบกำหนดและสถานะจริง โดยไม่นับรายการที่เสร็จสิ้นแล้ว

- ช่วยเรียบเรียงข้อเท็จจริง
- ช่วยร่างบทวิเคราะห์และข้อเสนอแนะ
- ช่วยตรวจความสอดคล้องของเนื้อหา
- แสดงแหล่งข้อมูลประกอบร่างเมื่อมีข้อมูลอ้างอิง

หลักการใช้งาน:

- AI ช่วยจัดทำร่าง เจ้าหน้าที่เป็นผู้ตรวจสอบ
- แยกข้อเท็จจริง ข้อวิเคราะห์ และข้อมูลที่ยังขาด
- หากหลักฐานไม่เพียงพอ ให้ระบุว่าต้องขอข้อมูลเพิ่มเติม
- ไม่สร้างเอกสารอ้างอิงหรือข้อเท็จจริงที่ไม่มีแหล่งรองรับ
- กุญแจ API ของ AI ต้องเก็บในระบบหลังบ้าน

## 14. การเปิดเว็บไซต์บน GitHub Pages

เมื่อเพิ่ม `index.html` และไฟล์ที่เกี่ยวข้องแล้ว:

1. เปิด repository `urr2556-png/non-audit-sao`
2. ตรวจว่า `index.html` อยู่ในโฟลเดอร์หลักของ branch `main`
3. เปิด **Settings → Pages**
4. ตั้ง **Source** เป็น **Deploy from a branch**
5. เลือก branch **main**
6. เลือกโฟลเดอร์ **/(root)**
7. กด **Save**
8. ตรวจผลการเผยแพร่ในแท็บ **Actions**
9. เมื่อเผยแพร่สำเร็จ เปิดเว็บไซต์จากปุ่ม **Visit site**

ที่อยู่ตามรูปแบบ GitHub Pages สำหรับ repository นี้:

https://urr2556-png.github.io/non-audit-sao/

ลิงก์นี้จะเปิดหน้าเว็บได้หลังเผยแพร่สำเร็จ เอกสารนี้ยังไม่ได้ยืนยันว่าเว็บไซต์ออนไลน์แล้ว

สำหรับเว็บไซต์ HTML/CSS/JavaScript ที่ไม่ต้องใช้ Jekyll สามารถเพิ่มไฟล์ว่าง `.nojekyll` ไว้ที่โฟลเดอร์หลักของแหล่งเผยแพร่

## 15. การแก้ปัญหาเบื้องต้น

| อาการ | จุดที่ควรตรวจ |
|---|---|
| หน้าแรกขึ้น 404 | มี `index.html` ตัวพิมพ์เล็กและอยู่ในแหล่งเผยแพร่หรือไม่ |
| ไม่พบปุ่ม Visit site | ตรวจว่าการเผยแพร่สำเร็จหรือมีข้อผิดพลาดใน Actions |
| รูปภาพไม่ขึ้น | อัปโหลดภาพครบหรือไม่ ชื่อและเส้นทางตรงกับโค้ดหรือไม่ |
| กดเมนูแล้วขึ้น 404 | มีไฟล์ปลายทางและชื่อไฟล์ตรงกับลิงก์หรือไม่ |
| หน้าเว็บเก่า | ตรวจ commit ล่าสุด ผลการเผยแพร่ และรีเฟรช browser |
| ลงทะเบียนไม่ได้ | ตรวจบริการ Auth และค่าการเชื่อมต่อ |
| ข้อมูลไม่เชื่อมกัน | ตรวจ API ฐานข้อมูลกลาง และสิทธิ์การเข้าถึง |
| AI ใช้งานไม่ได้ | ตรวจระบบหลังบ้านและค่าบริการ AI |
| สถิติไม่แสดง | ตรวจการโหลดข้อมูลและข้อความแจ้งข้อผิดพลาด |

การแก้ README เพียงอย่างเดียวไม่ได้สร้างระบบลงทะเบียน ฐานข้อมูล หรือหน้าย่อยให้ทำงานอัตโนมัติ

## 16. การจัดการข้อมูล

- แยกข้อมูลภายในออกจากข้อมูลสาธารณะ
- ไม่อัปโหลดรหัสผ่าน กุญแจลับ หรือเอกสารภายในลง repository สาธารณะ
- เผยแพร่เฉพาะข้อมูลที่ได้รับอนุมัติ
- เก็บประวัติผู้แก้ไขและเวลาที่เปลี่ยนแปลงข้อมูล
- สำรองข้อมูลและทดสอบการกู้คืน
- ป้องกันการอ่านและแก้ไขข้อมูลเกินสิทธิ์
- ไม่ใช้ข้อมูลใน browser เป็นหลักฐานยืนยันสิทธิ์ผู้ดูแลระบบ

หากใช้ `localStorage` เพื่อทดสอบ ข้อมูลจะอยู่เฉพาะ browser นั้น ไม่ใช่ฐานข้อมูลกลางและไม่ใช่สถิติผู้ใช้ทั่วทั้งระบบ
